### guestbook_form

- 메시지 입력 라벨: 남기실 말씀
- 보내기 버튼: 남기기

- 전송 성공: 소중한 말씀이 방명록에 남았습니다. 감사합니다. (`gb-success`)
- 전송 실패: 말씀을 남기지 못했습니다. 잠시 후 다시 눌러 주세요. (`gb-failed`)
- 메일 제목(스크립트 속성 `MAIL_SUBJECT`): [청첩장] 인혁 · 유민 방명록

- 2026-10-13 고침: 글이 두 사람에게만 전해지지 않고 페이지 목록에 바로 올라가므로, "보내다"와 "전달되다"를 버튼 "남기기"와 같은 동사 "남기다"로 바꿨다.
  - `gb-sending`: 보내는 중… → 남기는 중…
  - `gb-success`: 소중한 말씀이 잘 전달되었습니다. 감사합니다. → 소중한 말씀이 방명록에 남았습니다. 감사합니다. (2026-10-10 사용자 문구의 짜임은 그대로 두었다)
  - `gb-failed`: 말씀을 보내지 못했습니다. → 말씀을 남기지 못했습니다. 이제 `guestbook_form_errors`에 따로 적은 오류 밖의 모든 실패(`invalid`, `server`, 네트워크 오류, 15초 시간 초과)에 쓴다.
  - 메일 제목: hidden `_subject` 입력칸이 없어지고, 같은 문구를 Apps Script 스크립트 속성 `MAIL_SUBJECT`에 넣는다.

- 비밀번호 도움말: 글을 삭제할 때 필요합니다. 4~20자로 정해 주세요. (`gb-password-help`, 마크업. 입력칸의 `aria-describedby`로 잇는다)
- 비밀번호 비었을 때: 비밀번호를 정해 주세요. (`gb-password-empty`)
- 비밀번호가 4자보다 짧을 때: 비밀번호는 4자 이상으로 정해 주세요. (`gb-password-short`)
- 함정 칸(`website`) 라벨: 이 칸은 비워 두세요. (`gb-honeypot-label`, 마크업. 화면 밖에 숨긴 칸이라 CSS를 불러오지 못했을 때만 보인다. 설계 7장 목록 밖에서 더했다)

- 비밀번호 20자 초과, 성함 40자 초과, 말씀 500자 초과는 입력칸 `maxlength`가 막으므로 문구를 두지 않는다.

### guestbook_form_errors
새 글을 보냈을 때 서버가 `ok: false`로 답하면 `error` 값에 따라 쓴다.
- `rate_limited`: 지금 말씀을 남기시는 분이 많습니다. 잠시 후 다시 눌러 주세요. (`gb-error-rate-limited`)
- `duplicate`: 같은 말씀을 이미 남기셨습니다. (`gb-error-duplicate`)
  - 첫 전송은 저장됐는데 응답을 받지 못해 다시 누른 경우일 수 있다. 이 오류가 오면 목록을 다시 불러오기를 권한다.
- `closed`: 방명록은 이제 새 글을 받지 않습니다. 마음 써 주셔서 감사합니다. (`gb-error-closed`)
- 그 밖의 실패: `gb-failed` (위 `guestbook_form`)

### guestbook_list
- 목록 제목(h3): 남겨 주신 말씀 (`gb-list-title`, 마크업)
- 불러오는 중: 말씀을 불러오는 중입니다. (`gb-list-loading`)
- 글이 없을 때 (`gb-list-empty`, 2행):
  ```
  아직 남겨진 말씀이 없습니다.
  가장 먼저 축하를 전해 주세요.
  ```
- 불러오기 실패: 말씀을 불러오지 못했습니다. (`gb-list-failed`)
- 다시 시도 버튼: 다시 불러오기 (`gb-list-retry`, 마크업)

- 2026-10-14 지움: 말씀 더 보기 (`gb-more`, 마크업). 목록을 페이지 번호 방식으로 바꿔 버튼이 없어졌다.

### guestbook_pager
목록 아래의 페이지 이동 영역이다. 한 페이지에 글 5개, 페이지 번호는 최대 5개를 보인다. `{n}`, `{total}`은 script.js가 채운다.
- 이동 영역 접근성 이름: 방명록 페이지 (`gb-pager-aria`, 마크업, `aria-label`)
- 이전 버튼 접근성 이름: 이전 페이지 (`gb-page-prev`, 마크업, `aria-label`. 화면에는 화살표 아이콘만 보인다)
- 다음 버튼 접근성 이름: 다음 페이지 (`gb-page-next`, 마크업, `aria-label`. 화면에는 화살표 아이콘만 보인다)
- 번호 버튼
  - 보이는 글자: {n} (숫자만이라 script.js가 만든다)
  - 접근성 이름: {n}페이지 (`gb-page-number-aria`, `aria-label`. 보이는 숫자를 포함한다)
  - "현재"는 넣지 않는다. 현재 페이지 버튼의 `aria-current="page"`를 화면 낭독기가 "현재 페이지"로 읽으므로, 넣으면 두 번 읽는다.
- 페이지를 넘긴 뒤 알림: {total}페이지 중 {n}페이지 (`gb-page-status`, 상태 메시지)
  - 사진 카운터 `lb-counter`({total}장 중 {n}번째 사진)와 같은 짜임이다.
  - 페이지를 넘기면 포커스는 목록 제목으로 옮기고(모션 명세 4-8-1), 이 문구를 화면에 보이지 않는 상태 메시지로 함께 알린다. 목록 제목만으로는 몇 페이지인지 알 수 없기 때문이다(2026-10-14 구현에 맞춤).

### guestbook_expand
3줄이 넘는 글은 3줄까지만 보이고, 아래쪽이 흐려지며 작은 아래 화살표가 붙는다. 글을 누르면 펼쳐지고, 다시 누르면 접힌다. 화살표가 실제 버튼이며 보이는 글자는 없다(2026-10-14 사용자 결정).
- 화살표 버튼 접근성 이름(접힌 상태): {name}님의 글 펼치기 (`gb-expand-aria`, `aria-label`)
- 화살표 버튼 접근성 이름(펼친 상태): {name}님의 글 접기 (`gb-collapse-aria`, `aria-label`)

- 버튼이 글마다 붙어 화면 낭독기의 버튼 목록에 같은 이름이 여러 개 나오므로, 삭제 버튼 `gb-delete-aria`처럼 성함을 넣어 어느 글의 버튼인지 밝힌다.
- 보이는 글자 "펼치기"(`gb-expand`), "접기"(`gb-collapse`)는 2026-10-14에 지웠다. 사용자가 글자 버튼 대신 흐림과 화살표로 암시하는 방식을 골랐다.

### guestbook_delete
목록 항목의 삭제 버튼을 누르면 그 항목 안에 펼쳐지는 흐름이다.
- 삭제 버튼(보이는 글자): 삭제 (`gb-delete`)
- 삭제 버튼 접근성 이름: {name}님의 글 삭제 (`gb-delete-aria`, `aria-label`. 보이는 글자 "삭제"를 포함한다)
- 비밀번호 입력 라벨: 남기실 때 정하신 비밀번호 (`gb-delete-password-label`)
- 확인 버튼: 삭제하기 (`gb-delete-confirm`)
- 취소 버튼: 취소 (`gb-delete-cancel`)
- 삭제 중 버튼 라벨: 삭제하는 중… (`gb-deleting`)
- 삭제 성공 알림: 글을 삭제했습니다. (`gb-delete-success`)
- 비밀번호 비었을 때: 비밀번호를 적어 주세요. (`gb-delete-password-empty`)
  - 4자보다 짧은 비밀번호는 맞을 수 없으므로 따로 문구를 두지 않는다. 서버에 보내지 않고 `gb-error-wrong-password`를 보여 줘도 된다.

서버가 `ok: false`로 답하면 `error` 값에 따라 쓴다.
- `wrong_password`: 비밀번호가 맞지 않습니다. 다시 확인해 주세요. (`gb-error-wrong-password`)
- `too_many_attempts`: 비밀번호가 여러 번 맞지 않았습니다. 10분 뒤에 다시 시도해 주세요. (`gb-error-too-many-attempts`)
- `not_found`: 이미 삭제된 글입니다. (`gb-error-not-found`)
  - 하객이 지웠거나 두 사람이 시트에서 숨긴 글이다. 이 오류가 오면 목록에서 그 항목을 빼기를 권한다.
- 그 밖의 실패(`server`, 네트워크 오류, 시간 초과): 글을 삭제하지 못했습니다. 잠시 후 다시 눌러 주세요. (`gb-delete-failed`)

### guestbook_date
