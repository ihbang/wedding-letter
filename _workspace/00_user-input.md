## 갤러리 방식 변경 (2026-10-10, 커밋 179dd01 이후)

사용자 요청: "갤러리를 지금처럼 썸네일을 쭉 보여주는 방식이 아니라 한장씩 옆으로 넘기는 방식으로 변경"

- 3열 x 5행 썸네일 그리드를 없애고, 한 화면에 사진 1장씩 보여 주는 가로 슬라이드(캐러셀)로 바꾼다.
- 이 결정은 컨셉 시트의 갤러리 그리드 명세(3열, 2:3 셀, 행 단위 챕터)보다 우선한다. 사진 순서(02 01 08 / 03 09 12 / 07 13 05 / 11 06 14 / 10 04 15)와 alt는 그대로 쓴다.
- 오케스트레이터가 사용자에게 알린 기본값(사용자가 따로 바꾸지 않았다):
  - 한 화면에 사진 1장, 좌우 스와이프와 이전/다음 버튼으로 넘긴다.
  - 썸네일 목록은 없애고 현재 위치를 "3 / 15"처럼 숫자로 표시한다.
  - 자동으로 넘어가지 않는다.
  - 사진을 누르면 기존 lightbox(핀치 줌)가 열린다.
  - 가로 사진 2장(02, 15)이 지나치게 잘리지 않도록 슬라이드 비율을 정한다.
- 갤러리 순서 변경(사용자 요청: "첫 장을 01로 바꿔줘"): 캐러셀 첫 장이 가로 사진(02)이면 위아래 여백이 큰 화면으로 시작하므로, 1번과 2번을 맞바꾼다. 새 순서는 01 02 08 / 03 09 12 / 07 13 05 / 11 06 14 / 10 04 15이며, 컨셉 시트와 카피 시트의 갤러리 순서보다 우선한다. 각 사진의 alt 문장은 파일별로 그대로 쓴다.

## D-day 문구 변경 (2026-10-11)

사용자가 `_workspace/02_copy-writer_copy.md`의 `dday_message`를 새로 썼다(예식 전 "인혁 · 유민의 결혼식까지 / D - {n}", 당일 "오늘, / 저희 두 사람이 첫걸음을 내딛습니다.", 예식 후 "함께 걸어가는 {n}번째 날 / 끝까지 축복해 주셔서 감사합니다."). 사용자 확인으로 정한 것:

- 예식 후 `{n}`은 예식일을 1번째 날로 센다. 예식 다음 날(2027-01-04, KST)이 "2번째 날"이다.
- 큰 카운터는 예식 전에만 "D - {n}"으로 보여 준다. 당일과 예식 후에는 문구만 표시한다.

오케스트레이터가 정한 기본값:

- "첫 걸음"은 표준 표기 "첫걸음"으로 고쳤다(카피 시트에도 반영).
- 예식 전 화면의 "D - {n}"은 스크린 리더가 "디 마이너스"로 읽으므로 시각 텍스트는 `aria-hidden`으로 두고, 숨은 텍스트 "{n}일 남았습니다."를 대신 읽게 한다.

## 오시는 길 지도 추가 (2026-10-12)

사용자 요청: "오시는 길에 장소 정보와 지도 버튼만 나와 있는데, 네이버 지도 혹은 카카오맵의 지도를 inline으로 넣고 싶어"

사용자가 고른 것:

- 지도 서비스는 카카오맵이다. 카카오 공유에 쓰는 JavaScript 키를 그대로 쓴다.
- 고정 지도로 넣는다. 드래그와 확대를 막고 예식장 마커만 보여 준다. 자세히 보려면 지도 아래 기존 지도 버튼(네이버 지도, 카카오맵)을 쓴다.

오케스트레이터가 정한 기본값:

- 위치는 주소 "서울 송파구 송파대로 155"를 카카오 지오코더로 찾아 정한다. 좌표를 코드에 직접 적지 않는다.
- 지도는 오시는 길 섹션이 화면 가까이 왔을 때만 SDK를 불러온다. SDK 로드나 주소 검색이 실패하면 지도 영역을 숨기고, 장소 정보와 지도 버튼은 그대로 둔다.
- 지도를 눌러도 따로 동작하지 않는다.
- 사용자가 할 일: 카카오 디벨로퍼스 앱에서 카카오맵 사용 설정을 켜고, Web 플랫폼에 배포 도메인(`https://ihbang.github.io`)이 등록되어 있는지 확인한다. 로컬 미리보기에서 지도를 보려면 `http://localhost:8000`도 등록한다.

## 보케를 작은 전구 불빛으로 (2026-10-12)

motion-designer의 진단: 빛망울 색(glow `#EBCB94`, L* 83)이 바탕(`#FBF6F1`, L* 97)보다 어두워서, 빛을 그릴수록 바탕보다 어두운 얼룩이 생겼다. 여기에 가장자리 없는 번짐, 큰 것일수록 흐린 구조, 낮은 불투명도 상한이 겹쳐 "디스플레이가 눌린 자국"처럼 보였다.

개선안 A(렌즈 보케), B(작은 전구 불빛), C(전구 줄), 없애기 중에서 사용자가 **B**를 골랐다. 시험 구현과 캡처는 `scratchpad/bokeh-redesign/`에 있다(`build/engine.js`, `build/cfg-b.js`, `shots/compare-*.png`).

- 모양: 심 지름 5~9px를 `#FFFCF8`(바탕보다 밝음)로 채우고, glow 후광을 3.6r까지 둔다. 후광 알파는 심 바로 밖 0.9 → 0.5 → 0.2 → 0이고, 색은 glow 100%다.
- 움직임: 수명 9~16초, 1.2초 페이드, 밝기 1↔0.5 반짝임(주기 2.4~4.8초). 거의 제자리에 머문다(상승 0~3px/s, 흔들림 2~5px). 구간당 8개.
- 글자 대비는 불투명도 상한 대신 글자 영역 회피로 지킨다. `data-bokeh-exclude="text"`는 글자 줄 상자만, 값 없는 `data-bokeh-exclude`는 요소 상자 전체를 제외한다. BGM 버튼 자리도 제외하고, reveal이 끝난 뒤 제외 영역을 다시 잰다.
- 캔버스 DPR은 1에서 min(dpr, 2)로 바꾼다.
- 구간은 hero, calendar, closing이다. reduced-motion에서는 hero에 정지 불빛 7개를 둔다.
- 이 결정은 컨셉 시트 motion_direction의 불투명도 상한·흰색 보케 금지·색 비율과, 모션 명세 1장의 수치보다 우선한다.
